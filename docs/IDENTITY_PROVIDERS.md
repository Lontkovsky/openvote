# Identity provider contracts

Checked against official public sources on 2026-09-06. Only the test A/B contract is executable. No production endpoint, payload, certificate parser or callback has been invented. `IdentityProvider<Request, Assertion>` is an internal typed boundary; it does not imply that production providers share the mock wire format. Every production adapter returns `AwaitingProviderContract` and rejects authentication without a network call. Production configuration rejects the mock adapter before transport.

## Dependency and outage policy

A and B run as two independently controlled local mock processes with different signing keys, but their host and fixture definition are shared. This simulates provider failures, not organizational independence. Banks selected through BankID share the NBU central node. A concrete QES provider and Дія.Підпис may share trust or revocation dependencies; independence cannot be claimed without the actual deployment contracts. An unintegrated production adapter is not an available recovery channel.

The UI shows observed A/B availability and refreshes it only on entry or an explicit user action. An unreachable transport is labeled as an unreceived response; invalid status data is rejected. No automatic provider switch or weaker identification exists. A failed return keeps the same attempt in component memory, with at most three explicit deliveries. Selecting another provider is explicit; the backend deduplicates the same verified person. Late/concurrent returns for one completed attempt return the same sealed session token. A discarded component does not sign the user in after its response arrives. A reload loses the pending page state and requires identification again; it does not reset the voting right.

Issued credentials remain valid until the fixed close under the predeclared frozen-registry policy. An outage does not extend a poll. Revoking an identity prevents subsequent sessions/claims but does not erase an already exported credential from the native frozen registry. This residual limit remains open in the revocation work; it is not silently relaxed during an incident.

## Verification

`pnpm exec vitest run tests/providers.test.ts` checks real standard signatures, replay/request/freshness binding, unauthorized signatures, malformed status, disabled contracts and rejection of production mocks. It uses simulated HTTP responses and does not claim a real production integration. `tests/services.test.ts` independently exercises the two live mock processes, concurrent A/B deduplication, delayed return, both outages, conflicting attributes, same-credential recovery and native voting. Its expiry test waits until the private mock control confirms an in-flight response, then expires exactly that attempt. The pre-fix service incorrectly returned HTTP 200; the fixed transaction rechecks expiry before granting a session. Browser assertions are recorded separately by the existing in-app Browser runner.
